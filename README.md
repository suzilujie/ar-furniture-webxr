# AR 家具摆放 · WebXR 版

Week 1–2 的交付物。目标不是「做好作品」，而是**先把 3D 心智模型与基础交互跑通**：尺度、光照、相机、帧率、放置。

## 怎么跑

双击 `start.bat`（或 `start.ps1`）。

浏览器会自动打开 `http://localhost:5180`。

> 不要直接双击 `index.html`。WebXR / ES module 在 `file://` 协议下无法加载，必须走本地服务。

手动启动（等价）：

```bash
cd webxr
node server.js          # 端口 5180，可用 PORT=xxxx 覆盖
```

## 现在有什么

| 内容 | 说明 |
|---|---|
| 一张三人沙发 | 代码生成，2.00 × 0.90 × 0.87 m，无外部素材 |
| 地面 + 网格 | 网格间距 0.5 m，用来肉眼校验尺度 |
| 绿色标尺 | 高度 1.00 m，判断模型是否「太大 / 太小」 |
| 三种模式 | 视角 / 摆放 / 调整，底部工具条切换 |
| 点击放置 | 「摆放」模式下点击地面放下沙发，半透明预览跟随指针 |
| 拖动移动 | 「调整」模式下按住家具拖到任意位置 |
| 旋转与删除 | 选中后可左转/右转 15°、删除、一键清空 |
| FPS 读数 | 右上角，低于 55 变橙、低于 35 变红 |
| VR 按钮 | 桌面浏览器显示 `VR NOT SUPPORTED`，属预期；接头显后可用 |

## 三种模式（为什么不做「智能手势识别」）

拖动家具、旋转视角、点击放置这三件事在触摸屏上会**抢同一个指针事件**。Week 2 阶段用模式按钮明确划分，比手势识别可靠得多。

| 模式 | 能做什么 | 相机 |
|---|---|---|
| 视角 View | 拖动旋转、滚轮缩放 | 可操作 |
| 摆放 Place | 移动指针，点击放下家具 | 锁定 |
| 调整 Edit | 拖动家具、旋转、删除 | 锁定 |

> 相机在摆放/调整模式下被锁定是**有意的**：避免「想拖家具结果转了视角」。要换视角就点回「视角」。

快捷键：`R` 重置视角、`G` 切网格、`Q`/`E` 旋转选中家具、`Del` 删除选中。

## 目录结构

```
webxr/
├── index.html          入口 + 工具条 + 运行错误提示条
├── src/
│   ├── main.js         渲染器 / 场景 / 相机 / 光照 / 循环 / 工具条绑定
│   ├── interaction.js  模式状态机、射线拾取、放置、拖动、旋转、删除
│   ├── furniture.js    程序化家具（Week 4 换成 glTF）
│   └── hud.js          FPS 读数
├── vendor/three/       本地内置 three.js r170 + 所需 addons
├── server.js           零依赖静态服务
├── start.ps1 / .bat    一键启动
└── README.md
```

## 为什么把 three.js 放本地

- 不依赖 CDN（`unpkg` 在部分网络环境不可达，实测本机就不通）
- 可离线运行、可直接推 GitHub Pages
- 版本锁定在 0.170.0，避免上游更新导致行为漂移

升级方式：`npm pack three@<version>` → 替换 `vendor/three/` 下的同名文件。
